# Что действительно найдено в OEM API Android 13 (8052 OTA, октябрь 2026)

Основа: оригинальная OTA 8052, ZIP проверен SHA256. APK обработаны JADX 1.5.6, динамические символы библиотек — readelf. Исходный OEM-код и приватные данные не публиковались. **На живом проекторе вызовы не проверялись.**

## Проверенные интерфейсы

| Функция | OEM-класс / библиотека | Что подтверждено | Статус переноса |
|---|---|---|---|
| Управление аппаратными регистрами | `I2CDevice` (Factory, TvSettingsPlus, KeystoneCorrection) | JNI exports `open`, `readRegister`, `writeRegister`, `close` | Только через проверенный OEM-метод, прямые записи запрещены до проверки регистров |
| Шина контроллера | `Factory.ProjectorManager` | Обращение к `/dev/i2c-1`; второй параметр `open()` декомпилятор показал как ссылку на константу | Адрес устройства, права, ioctl и семантика регистров не известны |
| Ориентация проектора | `ProjectorManager.getProjectorMirrorMode()`, `setProjectorMirrorMode(Context,int)` | Методы извлечены из приложения Factory; TvSettingsPlus вызывает одноимённый метод | Прототип после проверки вызова через штатный UI |
| Автофокус | `IProjectorCtrl.getAutoFocusBoot()/setAutoFocusBoot(boolean)`, `getAutoFocusMove()/setAutoFocusMove(boolean)` | Binder-контракт обнаружен в OEM-приложениях | Высокий приоритет — необходим контроль разрешений |
| Трапеция | `IProjectorCtrl.getAutoKeystoneBoot()`, `setAutoKeystoneBoot(boolean)`, `getKeystoneValue()`, `resetKeyStone()` | Методы Binder-контракта подтверждены | Требуются замеры диапазонов и проверка сохраняемости |
| Геометрия | `KeystoneUtil.setLTOffset(int,int)`, `setRTOffset(int,int)`; `IProjectorCtrl.setKeystoneValue(...)` | Подтверждены сигнатуры методов | Не использовать значения наугад |
| Фокус вручную | `RuiCameraApi.MotorFrontStep(int)`, `MotorBackStep(int)`, `MotorStop()` | Подтверждены методы; моторный JNI в `librjpj_private_function.so` | Риск движения; нужны лимиты, проверка текущей позиции, аварийная остановка |

| Выбор HDMI | `KuSourceRJ.BootSoureActivity.setBootSource(int)` | Внутренний метод OEM-приложения, не публичный API | Идентификаторы HDMI 1/2 и способы безопасного вызова ещё не проверены |
| Поддержка автоматической трапеции | `libtrdmiddle.so` / `TrapezoidUtil` | JNI-экспорты для AutoTrapezoid и корректировки по вертикали/горизонтали | Сохранять OEM-библиотеку и аппаратную реализацию |

## Что означает наличие JNI для TvSettingsPlus

В OTA 8052 обнаружены `libsettingsi2c_jni.so`, `libfactoryi2c_jni.so`, `libi2c_jni.so`. Для каждого файла readelf подтвердил JNI-экспорты `open/readRegister/writeRegister/close`. Разные пакеты используют разные имена JNI-классов. Это **не** единая межприложенческая API, которую стороннее приложение сможет просто вызвать без соответствующего класса и доступа к устройству.

Декомпиляция также содержит `ProjectorManager.i2c(boolean)`; точный смысл аргумента `boolean` и регистров подтверждать на устройстве, а не угадывать.

## Как строить наше расширенное меню

1. Отдельное приложение интерфейса без прямых операций с /dev/i2c и ioctl.
2. OEM-адаптер: сперва только безопасные операции чтения состояний, затем через подтверждённый Binder или штатные публичные intent добавлять переключатели.
3. Для записи с системными правами может потребоваться отдельный привилегированный сервис/компаньон, согласованный с политикой SELinux и разрешениями Android. Установка APK под обычным пользователем не гарантирует доступ.
4. В адаптере обязательно различать профиль 8052 (1 HDMI) и 8054 (2 HDMI, ToF) и проверять реальные возможности устройства.
5. Для моторчика — ограничение шага, состояние занятости, безопасная остановка и журнал ошибок.
6. Не менять заводские параметры панели, I²C-регистры, EEPROM или калибровку до резервной копии и выяснения семантики.
7. Кнопки для разного HDMI, фокусировки, ориентации, изображения и геометрии подключать по одной после ADB-тестов.

## Двойной Bluetooth-аудиовывод

В `vendor/etc/audio_policy_configuration.xml` действительно есть три типа выходов: `AUDIO_DEVICE_OUT_BLUETOOTH_A2DP`, `AUDIO_DEVICE_OUT_BLUETOOTH_A2DP_HEADPHONES`, `AUDIO_DEVICE_OUT_BLUETOOTH_A2DP_SPEAKER`. Это **не три параллельных независимых выхода** и не доказательство поддержки двух пар наушников.

В `bluetooth_audio_policy_configuration.xml` отдельного подтверждения мульти-A2DP нет; профиль относится к Bluetooth Audio HAL и hearing aid. Требуется проверить активные Bluetooth-устройства, AudioPolicyManager и ограничения стека/HAL на самом проекторе. Функция A2DP Sink не входит в план.

## Provision

`Provision.apk` — не более старая версия фирменного `KuSetupWizard.apk`, а другой компонент первоначальной настройки. Оснований переносить Provision из 8053 нет. Сохраняем штатный мастер соответствующей прошивки.

## Что остаётся проверить на FlixTone/Everycom 8054

- Полная идентичность JNI-экспортов между октябрьской OTA 8052 и штатной 8054 (в архивном анализе 8054 методы I2C тоже найдены, но полное сравнение интерфейсов ещё не проведено).
- Какие Binder-сервисы реально зарегистрированы и какие разрешения нужны стороннему/привилегированному приложению.
- Точный диапазон фокуса и угол движения, ручной стоп; значения трапеции.
- Разрешённый безопасный способ выбора двух HDMI.
- Реальность двойного A2DP без замены Bluetooth/Audio HAL.

**Итог:** первый кандидат на интеграцию — OEM Binder `IProjectorCtrl` и штатные активности настроек, не запись регистров I²C напрямую.
