# Пошаговая реализация двух RUIOS Custom после завершения исследования

Документ фиксирует порядок будущей работы, **не является исполненным скриптом перепрошивки**.

## Замораживаем исходные оригиналы

- Для 8052: оригинальная OTA `RUIOS.8052.1.0.4` и factory backup; для 8054: последняя подтверждённая оригинальная factory/OTA той ревизии, которую реально получим.
- По SHA256 зафиксировать все разделы, APK и source properties, отдельно для каждой платы.
- Не подменять `boot`, `mboot`, `optee`, `vendor`, `tvservice`, `tvconfig`, `PMU`, `gamma`, `persist`, `factory` компонентами от другого SKU.
- Выход исследования — полная build manifest таблица `source image → input file hash → applied change → output file hash`.

## Фаза 1. OEM TV Settings и пульт

1. Разобрать `KuSettings` настройки, разобрать точное функциональное покрытие `TvSettingsPlus`, запомнить методы и сохранённые параметры.
2. Найти точную ветку ключа `TRD_POPMENU` / `MENU` в `GlobalKeyEventProcess`, не менять клавиши `FOCUS`, `FOCUS_PLUS`, `FOCUS_MINUS`, `FOCUS_RESET`, `SOURCE`.
3. Создать отдельную таблицу `OEM menu → AOSP/TV screen or OEM retained backend`, для отсутствующих экранов подготовить новый UI.
4. Восстановить привилегии штатного `com.android.tv.settings`: есть 20 привилегированных XML grants в текущей 8052, но переподписанный APK может потерять платформенную совместимость.
5. Испытать ярлык и кнопку Settings с резервным входом, до отключения `KuSettings`.

**Gate:** все пользовательские регулировки и аппаратные OEM backend вызываются без изменения I²C/JNI/kernel.

## Фаза 2. Общий FLauncher

1. Зафиксировать источник/коммит FLauncher, GPL-3.0 и зависимости Flutter; проверить аналитику/потребление памяти/Android 13 и архитектуру.
2. Подготовить универсальный HOME, настройки и источники через штатные Intent/Activities; без прямого HAL/motor/I²C вызова.
3. На обеих платформах подтвердить default HOME, D-pad, Home/Back, App install, startup после перезапуска и выход из сна.
4. Обеспечить fallback HOME и recovery через ADB; только затем удалить `zxlauncher` из сборки.
5. `zxstore` исключить, системный `PackageInstaller` обязательно сохранить.

**Gate:** HOME+Android TV Settings работает без китайского лаунчера и магазина.

## Фаза 3. Поэтапная очистка

- Удалять только доказанные независимые user applications, не весь `/system/app` по имени.
- `KuSettings` исключать после закрытия всех функциональных пробелов.
- `RJBluetoothSpeaker` (BT sink), `FTAirplayWireless`, `WFDSinkTest`, `RetailDisplay`, `TrdDreamPic`, сторонние preinstall APK — **вторая очередь**, решение отдельно с доказательством необходимости.
- `PackageInstaller`, `SystemUI`, `AutoPair`, `KuSetupWizard`, `TvServices`, `MtkTvInput`, TRD/Factory/ToF и нативные модули оставить в исходном виде.
- Не удалять ранние boot receiver и init service, пока не доказана их необязательность.

**Gate:** регрессионные испытания всех изменяемых путей на обеих ревизиях.

## Фаза 4. Общий UI поверх двух оригинальных аппаратных профилей

```text
stock-8052-matched-image + common-modifications + 8052 capability/profile
   -> proposed Custom 8052 image
stock-8054-matched-image + common-modifications + 8054 capability/profile
   -> proposed Custom 8054 image
```

- Никакого единого «универсального» ядра/TVservice/DTBO только потому, что APK совпадают.
- Общими будут изменения графического интерфейса и обработчики переходов, не рабочие `vendor` железные объекты.
- Запрещено менять `persist`, `factory`, `eeprom`, `project_id` на чужие или пустые из исходного ZIP.

## Фаза 5. Релиз (только после аппаратной диагностики и recovery)

- Подтвердить реальный метод загрузки и подписи; заранее иметь проверенное восстановление/откат.
- Запуск тестов `T001..T013` из [UNRESOLVED_AUDIT_GATES_RU.md](UNRESOLVED_AUDIT_GATES_RU.md) на одном 8052 и одном 8054, затем более широкая проверка.
- Распространять два пакета, каждый с проверкой модели/SKU/board marker, отдельной инструкцией и исходной совместимой стоковой версией.
- Вести changelog каждой поправки (зависимости, бинарные сравнения и регрессионные тесты).

## Критерии доказательного устранения багов в будущем

Не объявлять «исправлено» из-за смены версии. Каждая ошибка должна иметь:
- условия воспроизведения и устройство/версию;
- фактический изменённый метод/driver configuration;
- доказательство причины, исключение Wi-Fi/сети/Hardware вариаций;
- минимальную поправку и возможный откат;
- повторный тест обеих аппаратных профилей.
