# Архитектура будущего стокового кастома — 8052 (1 HDMI) / 8054 (2 HDMI)

**Дата:** 2026-10-21  
**Статус:** проектное решение по результатам офлайн-анализа, **не готовый прошиваемый образ**.  
**База:** оригинальная RUIOS Android 13, не LineageOS и не порт другой системы.

## Ключевой принцип

**Один репозиторий пользовательских патчей + две отдельные штатные базы = два установочных пакета.**

- `8052`: использовать проверенную **OTA RUIOS.8052.1.0.4** как источник актуального Android-содержимого; для полноты заводского комплекта иногда может понадобиться исходная 8052 PKG. Не подменять нетронутые разделы из 8054.
- `8054`: пока есть оригинальная заводская **RUIOS.8054.1.0.1**. Со слов владельца ожидается отчёт о работающей более свежей версии; **её оригинальные системные разделы для сборки ещё не получены**. До этого не считать 8052 .1.0.4 безопасной базой для 8054.
- Обе системы Android 13: общий код Android TV Settings, общая оболочка/launcher, общая логика запроса OEM возможностей, разные исходные разделы и аппаратные профили.
- `8053` не использовать как платформу для прошивки.
- Никакой изменённый образ не прошивать до проверки подлинной идентификации платы, AVB/OTA trust, бэкапа индивидуальных данных и реально доступного восстановления.

## Разделяем «общая программа» и «отдельная аппаратная база»

| Слой | Общий между 8052 и 8054? | Будущий подход |
|---|---|---|
| OEM GPU/VPU/audio/HDMI/PMU/TV HAL, boot, kernel, DTBO, EEPROM/calibration | **Не объединять автоматически** | Оставлять оригинальные от соответствующей ревизии, пока совместимость не доказана |
| UI Android TV, `TvSettingsPlus` (идентичен между исследованными версиями) | Да, исходный APK одинаковый | Единые изменения интерфейса Settings, подписанные/интегрированные по модели проверенных разрешений |
| `KuSettings`, `KuSourceRJ`, `KeystoneCorrection`, `trdservice`, `trdmiddle`, `Factory`, `RuiYunOta`, `TvServices`, `LiveTV`, `KuSetupWizard` | Текущие APK идентичны по SHA (см. анализ) | Общая карта зависимостей и интерфейсов; системные и аппаратные службы пока сохраняем |
| `RuiAutoFocus` | Нет | В каждом образе оставлять соответствующий оригинальный APK до подтверждения семантики отличий |
| `zxlauncher` | Отличается | Планируется удалить/заменить; общий новый HOME |
| `zxstore` | Отличается | Планируется удалить; не встраивать китайский магазин в новую систему |
| HDR/изображение/HDMI/ToF capability values | Отличаются как конфигурация и/или железо | Декларация профиля + runtime-проверка, показывать только реальные доступные настройки |
| OEM `tvconfig/bootdata` (`ConfigDefaultValue.ini`, gamma, PMU) | Частично | Не переносить значения из другой ревизии; сохранить профильную конфигурацию |

**Физические возможности для профиля:** `8052` — 1 HDMI, ToF в заводском props отключён; `8054` — 2 HDMI, ToF в заводском props включён. Наличие драйвера `stmvl53l1.ko` в образе 8052 не доказывает физический датчик. Не проверено, что любой FlixTone D11 идентичен плате Everycom 8054.

## Кандидаты на удаление и что останется

| Пакет | Решение для будущей модификации | Что должно остаться работоспособным |
|---|---|---|
| `com.zeasn.whale.saas` / zxlauncher | **Удалить** после установки и подтверждения собственного HOME | HOME, Back, меню приложений, реакция пульта, возобновление после сна, запуск Settings и HDMI |
| `zeasn.open.technical.tv.store` / zxstore | **Удалить** | Штатный PackageInstaller/установка APK, сетевые настройки, без зависимых обращений к компонентам магазина |
| `com.my.settings` / KuSettings | Пока **сохранить**; заменить только после функционального покрытия и тестов | Bluetooth, Wi-Fi, язык/время, системные настройки, OTA, явные Intent-контракты |
| `com.android.tv.settings` / TvSettingsPlus | **Сохранить и расширить**, не переписывать с нуля | Системные и аппаратные настройки, JNI, Binder, восстановление штатного пути открытия меню |
| `com.coolux.source`, `com.hysd.screen`, TRD, Factory, MediaTek TV services | **Сохранить** | HDMI, мотор/ToF, геометрия, калибровка, кнопки и sleep |
| `com.android.provision` / KuSetupWizard | **Сохранить** до проверки сценария первой загрузки и сброса | provisioning flags и последовательность первого запуска |
| `com.rjpj.yunota` | **Сохранить** пока нет проверенной альтернативы и rollback | Штатный OTA и system update |
| Другие рекламные/телеметрические приложения | Только после отдельного списка package/receivers/services | Нельзя удалять неидентифицированное приложение по имени/предположению |

**Доказательства:** `zxlauncher` и `zxstore` являются отдельными APK; OEM-меню уже присутствует в отдельных `KuSettings` и `TvSettingsPlus`. Последнее содержит `ProjectorFragment`, `FocusSettingsFragment`, `ProjectorModeFragment`, `KeystoneCalibrationActivity`, `SourceSubMenuController`, `PictureModeValueFragment` и I2C JNI. Межприложенческие Intent могут быть перенаправлены и протестированы отдельно.

**Принцип удаления:** пока анализ не завершён, ничего не удалять. При тестах сначала отключать пакет только для пользователя/через обратимый сценарий (с резервным HOME), а не вырезать из образа. Для финального образа проводить удаление/исключение файлов в сборочном дереве и отдельно восстанавливать нужные зависимости.

## Макет проекта сборки (проект, не созданные пока установщики)

```text
base/
  8052/original/           # отдельно идентифицированная OTA/stock PKG (не публиковать чужие бинарники без оснований)
  8054/original/
patches/
  common/
    apps/                 # общий будущий HOME
    tvsettings/           # единая логика меню
    permissions/
    system-config/
  profiles/
    8052/                 # 1 HDMI, ToF disabled, сохраняемые оригинальные файлы этой ревизии
    8054/                 # 2 HDMI, ToF enabled, оригинальные файлы другой ревизии
analysis/
  evidence/               # входные хеши, метод/ELF-дифф, матрица функций
out/
  RUIOS-custom-8052-*.pkg-or-ota
  RUIOS-custom-8054-*.pkg-or-ota
```

Папка `out/` — лишь схема; формат устанавливаемого обновления и безопасный путь восстановления **ещё не определены**.

## Проверки на уровне инсталлятора и регрессий (после завершения анализа)

1. Проверять OEM machine ID, HDMI port count, ToF property и независимый board marker, не полагаться на одну `getprop`.
2. Блокировать перенос boot/kernel/pmu/DTBO/gamma/calibration между профилями.
3. Выбирать исходный образ именно требуемой сборки/ревизии, сверять контрольные суммы.
4. Сохранять и читать права/signature/privapp-permissions/SELinux: замена системных настроек обычным APK может лишить их прав.
5. Проверить первый HOME, затем Settings, пульт, Wi-Fi/Bluetooth, оба HDMI (8054), фокус и геометрию, wake/standby, OTA, сброс/first boot.
6. Документировать откат до записи реальных разделов. Ключи тестового/заводского OTA сами по себе не доказывают приём пользовательских пакетов.

## Почему не просто одна прошивка на оба устройства

10+ важных OEM APK действительно идентичны. Это означает, что в пользовательском слое общий код реалистичен. **Однако одинаковые APK ≠ одинаковые платы, датчики или проверка загрузчика.** Сейчас безопаснее делать общие изменения *поверх двух оригинальных баз*, а не унифицировать низкоуровневые разделы в едином образе.
